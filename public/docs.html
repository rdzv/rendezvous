Your first rendezvous.

Run the host on the machine you want to share. Run the client where your agent executes commands. Use the same commands for your first session and every session after it.

1. Start the host

curl -fsSL https://host.rdzv.sh | sh

The bootstrap selects the current release, downloads and verifies it when needed, and starts a host session. A matching local copy is reused quietly.

Share the highlighted rv1.… invitation privately with your agent. Keep the host running. It displays Connected. when the guest authenticates. This is a new shell under your account, not a sandbox.

2. Join

curl -fsSL https://join.rdzv.sh | sh

Paste the invitation at the prompt, or include it in the command:

curl -fsSL https://join.rdzv.sh | sh -s -- --invitation 'rv1.…'

Direct invitations are visible in shell history and process arguments. To avoid placing the invitation there, supply an owner-only file instead. For automation, add --command:

curl -fsSL https://join.rdzv.sh | sh -s -- --invitation-file /private/path/invitation --command 'uname -a'

--invitation and --invitation-file are mutually exclusive. Interactive shells use your terminal; automated commands through the bootstrap receive no standard input.

3. End access

Exit the remote shell, press uppercase D or Ctrl-C on the host, or let the session deadline expire. No Enter is needed for host keyboard controls. Host-initiated shutdown closes SSH before the Tor transport. The first successful authentication consumes the invitation. Disconnect never reactivates it. One interactive connection can run many commands; --command runs one command and ends that session.

curl -fsSL https://host.rdzv.sh | sh -s -- --invite-timeout 300 --session-timeout 1800

Defaults are ten minutes to redeem and twelve hours of access. Both host and join support --session-timeout SECONDS; the earlier limit ends the connection. A new host invocation creates new service identities and credentials.

Join as an agent

curl -fsSL https://join.rdzv.sh | sh -s -- -a --invitation "<invitation>"

Agent mode keeps one SSH connection in the background and prints exact local commands. session exec SESSION 'command' runs a command, streams its stdout and stderr, and returns its exit code in one call. Each execution uses a fresh shell without a PTY. Use cd /path && ... for a specific working directory. The controller exits when the session ends or reaches its lifetime limit, which includes startup and approval waiting.

The homepage's Human / Agent switch copies a ready-to-paste agent prompt. Append your invitation to it; the website does not receive the invitation.

Approve agent commands

curl -fsSL https://host.rdzv.sh | sh -s -- --approve

This optional mode logs each complete exec request before asking Approve command?. Press a to approve it, d to deny it, or A to approve it and all subsequent requests. Denied commands do not execute and return exit status 126. Repeated unbound keys expand the prompt to Approve command (a/A/d)?. Approval requires a host terminal and agent mode; for interactive person-to-person access, start the host without --approve.

a: approve, A: approve all, d: deny, D: disconnect

Approval bindings appear in the bottom status bar only while a decision is pending. Only a/A are green and d/D red; all other bar characters remain gray. Outside a pending decision the bar shows only D: disconnect.

Watch the session

The host logs complete SSH exec commands and interactive input in red, with output in cyan and aligned neutral labels. Typed human input stays on the same log line until Enter. Host output logs follow logical line boundaries, with long lines shortened by default. Use --verbose for full host output logs:

curl -fsSL https://host.rdzv.sh | sh -s -- --verbose

Interactive human logs record keystrokes, including editing controls, rather than reconstructing executed commands. The human PTY combines STDOUT and STDERR; agent exec requests keep the streams separate. Guest command output is unchanged. See the CLI reference for every host, join, and agent-session option, generated from the current release's --help.

Supported environment

  • Linux x86_64, aarch64 (ARM64), or armv7l (32-bit ARM hard-float) with glibc 2.34 or newer: for example, Ubuntu 22.04+, Debian 12+, or Amazon Linux 2023, where the distribution supports that architecture. Both host and client support all three architectures.
  • Base command-line utilities: curl, tar, sha256sum, getconf, and standard shell utilities.
  • A writable home directory on a filesystem that permits execution. No root or sudo is required.
  • macOS, Windows, older glibc, and musl-based hosts such as Alpine are not packaged in this release. Unsupported platforms stop before installation instead of asking for elevation.

Inspect before installing

Read the shell installer or download it first:

curl -fsSLo install-rdzv.sh https://host.rdzv.sh/install
less install-rdzv.sh
sh install-rdzv.sh

Read the application and packaging source and bundle manifest. The runtime archive is delivered in fixed-size parts, joined locally, and verified as a whole before extraction. The installer's checksum is served by the same publisher; this is integrity checking, not an independent signature.

Startup and latency

Rendezvous reuses Tor's public directory cache to reduce repeated bootstrap downloads. Each session still creates fresh service keys, credentials, and Tor process state. Concurrent sessions use separate cache slots.

For a shorter host-side route, opt into Tor's experimental single-onion mode:

curl -fsSL https://host.rdzv.sh | sh -s -- --single-hop

This reduces the host-side introduction and rendezvous circuits from three hops to one and gives up host-location anonymity. Client routing, client authorization, SSH encryption, host-key pinning, and single-use access remain in place. Default routing is unchanged. Startup, service publication, and keystroke round-trip time depend on the Tor network; neither caching nor single-hop mode guarantees a particular delay.

Caching, updates, and removal

Every invocation of the website command fetches the current bootstrap. Releases and public Tor directory data are cached under ~/.local/share/rendezvous; ongoing sessions retain their existing runtime. Optional local launchers are also cached, but running them directly does not check for updates. No shell configuration is required for the website commands.

To remove the cached files, stop your sessions and remove ~/.local/share/rendezvous, ~/.local/bin/rdzv, and ~/.local/bin/rendezvous.

Troubleshooting

  • Waiting for the onion service: invitations are issued after descriptor-upload acknowledgments, and the client retries transport and handshake failures before credentials are sent. Connection attempts are bounded by the invitation's remaining lifetime and a three-minute connection deadline.
  • Connection lost during authentication: the invitation may have been consumed. Start a fresh host session rather than assuming it is reusable.
  • Permission denied after connecting once: start a new host session; the previous invitation is consumed.
  • Execution denied under home: local policy or a no-execute filesystem can prevent running the bundle. The installer does not bypass that policy.
  • Unsupported platform: no system packages are changed and no privilege prompt is attempted.
