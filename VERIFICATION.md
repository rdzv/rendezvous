## Native exec and approval release 0.2.6

- Agent mode now uses native, non-PTY SSH exec requests on one authenticated
  connection. `session exec SESSION COMMAND` returns stdout/stderr bytes directly
  and exits with the command's status. Shells are fresh per command. A separate
  SSH control channel supports graceful whole-session teardown; it runs no shell.
  Human interactive PTY mode remains available.
- Removed agent send/read, output records, fences, nonce tags, and injection-policy
  text. Tests compare exact stdout/stderr/status, including binary bytes, literal
  strings resembling the old wrappers, nonzero status, and output over two MiB.
- Optional `host --approve` gates each complete exec request before starting a
  subprocess. a approves one, d denies without execution (status 126), A switches
  to allow-all, and D disconnects. Pending-only footer text is exactly
  `a: approve, A: approve all, d: deny, D: disconnect`; only a/A are green and
  d/D red. Descriptions/punctuation remain neutral. The simple prompt escalates
  once after two unbound keys. Lowercase d no longer disconnects.
- Tests cover denial side effects, approval/allow-all, abandoned requests, caller
  termination killing its remote job, and rejecting interactive/PTY attempts to
  bypass approval. Real controlling-PTY tests verify keyboard handling and footer
  visibility; a terminal emulator verifies every key and non-key character's color.
- Host and client defaults are 43,200 seconds (12 hours), configurable with
  `--session-timeout`. A short-deadline test verifies the active remote process,
  SSH connection, controller, and socket are cleaned up. No post-close output
  retention process remains. The agent's lifetime includes startup/approval waiting.
- Source real-Tor test passed: publication 18.05 s; denial, one-command approval,
  allow-all, separate stdout/stderr, exit status 17, and fresh-shell behavior.
  Host D disconnected the active command in 0.989 s with status 130.
  Evidence: `/tmp/opencode/rendezvous-026-exec-source.log`.
- Final rootless portable-bundle test passed through the full piped host installer:
  publication 14.8 s; denial, single approval, allow-all, exact separate command
  output/status, and fresh shells verified. Host D stopped the active exec in
  1.048 s. Evidence: `/tmp/opencode/rendezvous-026-exec-bundle.log`.
- Local checks: 73 Python tests and 4 web tests passed. Semgrep: 219 applicable
  rules, zero findings across 25 Python/JavaScript targets. Both packaged modules

## Connection readiness and agent-session release 0.2.5

- Host startup subscribes to authenticated Tor HS_DESC events while networking
  is disabled, then enables networking and waits for upload acknowledgments from
  two distinct directories before issuing an invitation or starting its lifetime.
  Tests cover subscription ordering, wrong-service events, and duplicate uploads.
- The SSH login window is 120 seconds. Client transport/handshake failures retry
  within a three-minute/invitation-expiry deadline, but never retry after handing
  credentials to AsyncSSH. Wrong pins and rejected authentication fail immediately.
  Stage-specific timeout errors replace blank errors; rendered errors escape controls.
- D/d both disconnect; stale Escape prefixes expire instead of swallowing the
  next key. Controlling-PTY tests cover both letters and Ctrl-C. Incoming content
  is red, outgoing content cyan, neutral labels occupy one aligned column, and
  fragmented ANSI character-set selectors no longer leave stray B characters.
- `join -a` starts a detached client with one SSH connection and one shell channel.
  A private same-UID Unix socket supports send/read/help/close from independent
  processes. Tests verify persistent working directory/environment, read cursors,
  non-consuming reads, overflow reporting, terminal controls, path/permission
  rejection, and rejection of foreign peer UIDs before reading requests.
- Output is bounded by one MiB and 4096 events, with explicit overflow reporting.
  Final output is retained for up to fifteen minutes, including connection failures
  after a session was established. Remote data/errors are separated from local
  controls and wrapped as untrusted output. Invitations enter workers over a pipe.
- The homepage Human / Agent switch copies Jonathan's exact prompt, including

## Line-oriented host console release 0.2.4

- Normal-mode input appends in real time to one `[input]` line until CR/LF;
  UTF-8 input is decoded incrementally. CRLF is one boundary, even across reads.
  Output is buffered by logical line, not SSH read size. Long normal-mode output
  is bounded and shortened; verbose records retain their full content. Partial
  records are flushed before the final session status.
- Stateful ANSI parsing handles fragmented CSI/OSC sequences. Normal mode hides
  recognized bracketed-paste/readline prompts and their typing echo, and common
  plain prompts. Formatting/title controls are stripped only from the host log;
  guest data is unchanged. Verbose mode retains safely escaped prompt/control
  information. Newline-terminated program output resembling a prompt is retained.
- The startup control hint is replaced by a persistent bottom row containing
  only `D: disconnect`. The host's trusted renderer reserves the rows above it
  as the scroll area, follows SIGWINCH, and restores full scrolling on exit.
  Redirected output receives no status-bar escape sequences. Ctrl-C still works.
- Terminal-emulator tests verify the footer survives scrolling and wrapped,
  hostile-control-character input, resizing, and cleanup. Controlling-PTY tests
  cover D/Ctrl-C, actual SIGWINCH, piped stdin, redirected logs, and restoration.
  Prompt tests feed the reported Bash prompt sequence in 1-byte, 7-byte, and full
  chunks. Long input/output, split CRLF, verbose behavior, and pending shutdown
  records are covered. `pyte` is a development-test dependency, not bundled.
- CLI docs are regenerated from current help and describe the line-oriented log
  and persistent controls. Semgrep: 219 applicable rules, zero findings.
- Completed checks: 46 Python tests and 3 web tests passed; packaged runtime is
  byte-identical to source and excludes the test-only terminal emulator. Canonical
  installers, updated public help, full downloaded release checksum, and fresh/
  repeated published installation as rootless UID 10001 all passed.

## Host console and graceful-disconnect release 0.2.3

- Host logs complete SSH exec requests and an untruncated interactive-input
  transcript. Logs escape terminal/control/Unicode formatting characters.
  One-line output previews are the default; `--verbose`/`-v` logs complete
  outgoing PTY data. Guest bytes remain unchanged. The PTY combines stdout/stderr.
- Interactive input is not reconstructed shell execution: history, editing,
  expansion, and commands executed inside programs do not become separate SSH
  requests. Per-command approval was not added to the unrestricted interactive
  shell; the user's explicitly permitted logging fallback is implemented.
- Host controls read `/dev/tty` in cbreak mode even with piped installer stdin.
  Uppercase D cancels the host task; ISIG remains enabled for Ctrl-C. Actual
  controlling-PTY tests verify both keys and terminal restoration.
- Shutdown closes the SSH channel with a notice/exit status, waits up to five
  seconds for the guest to close SSH, and only then shuts down Tor. Local real
  SSH tests assert the guest receives the notice while Tor is still running,
  for both host cancellation and the session deadline.
- Tor uses its own OS session/process group so a terminal Ctrl-C cannot kill the
  transport before the host sends its notice. Explicit teardown and Tor's
  owning-process monitor remain in place; a subprocess test covers isolation
  and cleanup. The first live D test passed, while live Ctrl-C exposed this
  additional signal-propagation issue before release.
- CLI reference `/cli` is generated directly from actual general/host/join help
  during source-release builds. A test rejects stale help content. Provider
  deployment copy and frontend command rewriting were removed from public pages.
- Local checks: 37 Python tests passed across runtime/host console/installer/docs;
  3 web routing tests passed. Semgrep: 219 applicable rules, zero findings across
  19 Python/JavaScript targets. Final portable bundle matches runtime source.
- Live host-control runner: `tools/verify_host_controls.py`; evidence is recorded

- Final host-key parsing also ignores terminal escape sequences (including a
  fragmented left-arrow sequence ending in D); controlling-PTY tests cover it.
- The later live staging run passed both controls: Ctrl-C returned the interactive
